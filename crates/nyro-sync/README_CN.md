# nyro-sync

独立于数据库、网关应用和微内核生命周期的配置交付模块。

- `Hub<T>` 持有最新完整快照和节点交付、生效状态；JSON 对象键顺序不影响内容指纹。
- `http_router` 提供带认证的 `POST /v1/config/sync` 长轮询接口，由组装层挂载到 TLS 监听器或可信 TLS 终止代理之后，不自行创建监听器。
- `HttpClient<T>` 使用 HTTPS，仅允许回环 IP 使用明文 HTTP；禁用重定向和环境代理发现，限制响应大小并校验指纹。
- `Source<T>` 和 `run` 让 HTTP、memory 共用应用反馈及重试流程。调用方负责校验、激活及失败保留旧代际；`Applied` 必须表示激活已经完成。

快照可能包含上游凭证，因此不实现 `Debug`，响应禁用缓存，错误不包含正文或 URL。同步凭证与管理凭证、Consumer 凭证分开。

memory 交付不进行传输所需的序列化与解析，但计算指纹仍会序列化。节点五分钟未轮询后，其状态会过期；重新连接触发完整快照交互。配置正文上限 1 MiB；HTTP 单次等待 25 秒，客户端请求超时为 35 秒。

执行循环保留最近成功的指纹；通信失败按 500 毫秒到 30 秒指数退避，并重新取得完整快照。永久应用错误等待不同内容；可重试激活错误在重试前先取得最新快照。取消会中断轮询、等待和激活，调用方的激活函数必须满足取消安全。

根 `nyro` CLI 的 `proxy --server` 使用 HTTP，`serve --enable-proxy` 使用 memory。控制面关闭时，`Hub::close` 唤醒未完成的长轮询。这里不实现离线磁盘缓存、数据库访问、增量同步、gRPC、遥测传输或分布式计数。
