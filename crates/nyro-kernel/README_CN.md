# nyro-kernel

[English](README.md)

为静态组装的 Rust 应用提供与业务无关的资源生命周期和运行时代际管理。
实验性的源码构建根命令 `nyro proxy` 已使用本 crate 管理强类型运行代际和请求 lease。
现有 `nyro-core`、已发布的 `nyro-server` 和 Tauri 请求路径仍不依赖它。Rust API 仍处于实验阶段。

## 职责边界

内核负责依赖图验证、资源启动和回滚、运行时原子发布、代际 lease、旧代回收及退出。
仅依赖 Tokio、tokio-util 和 async-trait。

Bootstrap 构造强类型 `Candidate<T>`，串行处理配置比较、构建和激活。
版本和指纹只是外部传入的元数据；内核不会因指纹相同而跳过激活。
LLM 鉴权、路由、重试、流式业务规则、配置、HTTP、数据库操作和 Provider 目录均留在内核外。
纯编解码器不必实现空生命周期。没有全局注册表、服务定位器、动态加载或业务请求上下文。

## 所有权与保证

- 候选代构造不得启动任务、注册全局状态或修改线上运行时。所有分配都必须由 RAII 持有，
  即使候选代未启动就被丢弃或拒绝，也能释放。
- `activate()` 调用即转移所有权，丢弃返回的等待 future 不会取消事务。
  通过传入的 `Context.cancellation` 显式取消；发布后，此令牌不再影响新代。
  激活期限覆盖排队和启动，回滚另有新的清理预算。
- 启动前验证非空且唯一的 ID、依赖存在性和无环性。按拓扑顺序启动，同批就绪资源按 ID 排序。
  重复依赖不影响结果。
- 全部启动成功后，才将 `T` 和元数据一起发布。失败或取消不改变当前代。
  回滚覆盖失败组件及未启动组件的分配，已启动资源逆序停止。
  非法图不存在拓扑顺序，其分配按输入逆序清理。
- 每个克隆 lease 都会持有对应代，必须覆盖完整流式响应和必要收尾。
  普通重载没有强制排空超时；请求期限和取消由调用方负责。
  `Lease::cancellation()` 返回代际取消信号的独立子令牌。
- `shutdown()` 立即拒绝新 lease 和激活，取消进行中的启动。默认给已有 lease 30 秒排空，
  到期后取消残留代际使用，再给予独立的 5 秒清理预算；两者均可配置。
  无 lease 的代立即清理，不被阻塞的激活拖延。已在运行的清理保留更早的期限。
  零清理预算仍调用所有 `begin_stop`，但报告清理不完整。
- 按逆序逐个调用 `begin_stop()` 和 `wait_stopped()`，单个错误不会跳过其他资源。
  启动错误包含回滚错误；状态保留清理错误；退出汇总包含此前回收、回滚的清理失败。
  多次退出等待返回相同的完成结果，丢弃一个等待者不影响清理。
- 被拒绝的候选代不会启动，只同步调用所有者的 `begin_stop` 后销毁，不执行异步等待。
  `Host::drop` 发起后台退出；资源 Drop 仅是同步取消兜底，不表示清理完成。
  必须在停止 Tokio 之前等待 `shutdown()`。

生命周期方法、future 轮询及析构不得阻塞或 panic。启动和停止等待 future 必须可安全丢弃，
后台任务及其句柄仍由生命周期对象持有。每个组件的启动取消信号独立，在其 `begin_stop` 前触发；
依赖资源保持可用，直到依赖它的组件等待结束或清理超时。代际请求取消与组件停止信号分离。
停止上下文也使用独立的阶段信号，因此启动取消后仍可清理。期限只用于对应阶段。
这是进程内协作式管理，不是对不可信插件的隔离；超时无法抢占阻塞代码、撤销已有 `&T`，
也不能保证外部操作已停止。

`T` 作为整体代际切换，但内核无法保证内部句柄的深层不可变性。
进程级监听器、数据库连接池和真正共享的配额／健康状态由 bootstrap 持有。
代际组件只释放自己的绑定，不能关闭其他代仍在使用的共享资源。
`Status.accepting` 只反映内核是否接收新 lease，不等于完整业务健康状态。

## 示例与验证

[英文文档](README.md#example) 提供可执行的完整示例：强类型运行时和显式组装的后台 worker。
Worker 始终持有任务句柄，即使生命周期 future 被取消也不会失去所有权。

```sh
cargo test -p nyro-kernel
cargo clippy -p nyro-kernel --all-targets -- -D warnings
cargo tree -p nyro-kernel --edges normal
```
